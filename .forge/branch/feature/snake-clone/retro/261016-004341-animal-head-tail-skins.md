# 2026-10-16 — 동물 머리·꼬리 스킨 추가

## 계획 대비 실제
- 계획대로 된 것: 5개 슬라이스 모두 완료. 와이어에 별도 `animal: u8`을 추가했고(Q3-A), 머리·꼬리는 Canvas 벡터로 그렸으며(Q2-A), 선택 UI는 미리보기 + 동물 한 줄 + 색상 한 줄(Q5-A)로 만들었다. 테스트는 141개에서 155개가 되었고 모두 통과, typecheck 통과.
- 차이점:
  - `Snake` 생성자와 `spawnSnake`에 `animal`을 끝쪽 선택 인자(기본 0)로 붙였다. 필수 인자로 넣으면 기존 테스트의 호출 40여 곳을 모두 고쳐야 해서다.
  - 눈 그리기를 `Renderer`의 private 메서드에서 `animals.ts`의 `drawEyes`로 옮겼다. 시작 화면 미리보기가 같은 눈을 써야 했다.
  - 미리보기 뱀이 처음엔 너무 작았다(캔버스를 CSS로 절반 줄여 표시하는 것을 놓쳤다). 반지름을 12에서 26으로 키웠다.
  - 워크플로우 없이 메인 세션에서 직접 실행했다. 직렬 의존이고 규모가 작았다.

## 배운 점
- 다음에는 이렇게 한다:
  - 와이어 프로토콜에 바이트를 추가하는 작업은, 실행 전에 이미 떠 있는 서버(`tsx watch`)가 옛 코드로 돌고 있지 않은지 확인한다. 이번에 포트 8080의 기존 서버가 옛 `join`을 해석해 새 클라이언트의 입장을 거부할 수 있었다. 다른 포트로 서버와 vite를 따로 띄워 확인했다.
  - 이 프로젝트의 클라이언트 테스트 환경은 DOM이 없다(vitest node 환경). Canvas 그리기는 호출을 기록하는 목 컨텍스트로 테스트하고, 버튼 클릭 같은 DOM 연결은 브라우저로 확인한다고 계획 단계에서 미리 DoD에 적어 둔다. 이번 DoD 4번이 그 역할을 했다.
  - 미리보기처럼 캔버스 속성 크기와 CSS 표시 크기가 다르면 화면에서 실제 크기를 계산해 본다.
  - 같은 파일을 다른 미커밋 작업이 건드리고 있을 때는 선행 조건(작업 트리 클린)으로 먼저 정리한다. 이번에는 `ordinal` 작업을 별도 커밋(`ee63db0`)으로 분리한 덕에 커밋이 섞이지 않았다.
- 확인된 것: 별도 `animal` 필드 방식은 `skin`과 먹이 색 규칙을 전혀 건드리지 않아 기존 테스트가 거의 그대로 통과했다(픽스처에 `animal` 필드를 추가하는 변경만 필요했다).
